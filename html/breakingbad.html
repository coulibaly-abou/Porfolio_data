SAÉ 3.02 — Projet individuel

Vue d'ensemble du projet

Contexte

Objectif : concevoir et mettre en place une base de données décisionnelle dédiée à la série Breaking Bad, centralisant saisons, épisodes, lieux, personnages, actions liées au trafic de drogue, audiences et récompenses, à partir de sources hétérogènes (breakingbad.fandom.com et Wikipédia).

  • Python
  • BeautifulSoup
  • FME
  • PostgreSQL

Modélisation des données

Un Modèle Conceptuel de Données a d'abord formalisé les entités (saison, épisode, personnage, acteur, lieu, récompense, catégorie...) et leurs associations. Il a ensuite été décliné en modèle en étoile, autour d'une table de faits fait_apparition (durée, nombre de scènes, importance du rôle) reliée à sept dimensions, puis en modèle en flocon normalisé pour réduire la redondance (hiérarchie saison → épisode, personnage → acteur, récompense → catégorie).

Pipeline ETL

L'extraction repose sur un programme Python (requests + BeautifulSoup) qui parcourt le wiki de la série pour en extraire saisons, épisodes, résumés, réalisateurs, scénaristes et acteurs, exportés en CSV. Un script de nettoyage traduit ensuite les données de l'anglais vers le français et harmonise les caractères spéciaux. Le chargement final dans PostgreSQL est orchestré via des flux FME (Attribute Manager, Feature Merger, Duplicate Filter) qui alimentent une quinzaine de tables reliées par clés étrangères.

CREATE TABLE episode(
  id_episode INT PRIMARY KEY,
  titre TEXT NOT NULL,
  note_IMDB DOUBLE,
  id_saison INT REFERENCES saison(id_saison)
);

Exploitation SQL

Une dizaine de requêtes de test valident la base : personnages impliqués dans la vente de drogue par saison, audience moyenne par pays et par saison, récompenses par catégorie, ou encore distinction entre personnages principaux et secondaires — autant de cas d'usage typiques d'un entrepôt de données décisionnel.

15+ Tables reliées
2 Modèles (étoile / flocon)
10 Requêtes de validation

Conclusion

Ce projet individuel couvre l'ensemble d'une démarche décisionnelle : collecte par scraping, nettoyage et traduction, modélisation dimensionnelle et chargement ETL automatisé. Il illustre ma capacité à concevoir seul une base de données exploitable pour l'analyse, de la donnée brute jusqu'à la requête métier.
